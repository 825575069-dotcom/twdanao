## 关键决策

| 决策 | 理由 |
|---|---|
| 后端中转上传 OSS | 头像较小，便于统一鉴权、校验和密钥保护。 |
| 复用统一上传服务 | 避免按入口复制 OSS 领域逻辑。 |
| 按账号作用域生成对象键 | 总控与租户数据边界清晰，租户路径包含 `tenant_code`。 |
| 上传成功立即保存头像 | 避免 OSS 对象已创建但资料未保存的悬空状态。 |
| 使用 `OSS_ROOT_PREFIX` 规划 Bucket 根目录 | 支持不同部署共享 Bucket 时隔离，并让目录规则可配置、可审计。 |
| 账号头像路径包含服务端账号 ID | 便于归属追踪，且不信任前端提供路径身份。 |

## 错误记录

| 错误 | 次数 | 处理 |
|---|---:|---|
| 初次全局检索包含 `web/node_modules`，输出过大并截断 | 1 | 后续仅读取精确业务文件，不重复大范围检索。 |
| Git 无法创建 `.git/index.lock` | 1 | 沙箱只读 Git 元数据；改为申请仅暂存并提交设计文件的受限权限。 |
| 隔离 worktree 基线命令找不到 `yarn.cmd` | 1 | 当前 shell 未配置全局 Yarn；改用工作区捆绑运行时提供的 Yarn/Node 路径。 |
| 删除 `server/db.sqlite3` 后发现该文件仍受版本控制 | 1 | 确认为本次操作产生的无关删除，恢复基线文件；隔离分支最终状态为空。 |
| 首次恢复 `server/db.sqlite3` 无法创建 worktree `index.lock` | 1 | Git 元数据受沙箱保护；申请仅恢复该文件的受限权限后成功。 |
