# 真实 Compose 容器测试排查计划

## 目标

在 WSL 的现有 Docker Compose 容器中执行测试，区分容器挂载/环境问题与真实 MySQL 数据约束问题，并给出最小、可验证的修复路径。

## 阶段

- [x] 1. 收集失败输出、Compose 挂载和 pytest 设置证据
- [x] 2. 将失败按环境、测试隔离和真实数据库兼容性分类
- [x] 3. 确认修复设计与实施计划
- [x] 4. 实施代码与验证入口修复
- [ ] 5. 在 WSL 现有容器复验并记录结果

## 约束

- 不自动同步本地代码到 WSL；由用户 IDE 同步。
- 不删除开发库 `yesgo` 或 Redis 数据。
- 复用正在运行的 `backend`、`yesgo-mysql`、`yesgo-redis` 容器，不启动第二套服务。
- MySQL 测试数据库操作仅限 `test_yesgo`；Redis 使用独立逻辑库和测试键前缀，测试结束清理其新增数据。
