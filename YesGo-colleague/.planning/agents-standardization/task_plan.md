## 关键问题

1. 目标文件是否仅限根目录 `AGENTS.md`，还是同时建立分目录级 `AGENTS.md`？
2. 高频变化的细则应全部留在根文件，还是下沉到专题文档并由根文件索引？
3. 哪些规则属于不可违反的硬约束，哪些属于默认规范或当前阶段建议？
4. Harness Hook 应只做上下文加载，还是同时阻止未加载规则时的修改操作？

## 已做决策

| 决策 | 理由 |
| --- | --- |
| 为本任务建立独立 `.planning/agents-standardization/` | 避免污染已存在的 `list-filter-layout` 计划 |
| 不覆盖现有 `AGENTS.md` 未提交内容 | 该差异属于用户在途修改，必须保留 |
| 建立分层 Harness | 用户已确认，根文件承担总纲，子目录文件承担局部规则 |
| 分层规则集中到独立目录 | 用户明确否定将 `AGENTS.md` 散落在业务目录的方案 |
| Harness Hook 采用守卫型 | 用户明确选择；对写操作执行规则加载与完整性门禁 |
| 设计说明通过用户复核 | 可进入 `writing-plans` 阶段 |

## 错误记录

| 错误 | 尝试 | 处理 |
| --- | --- | --- |
| 沙箱并行读取技能文件时报 `CreateProcessAsUserW failed: 5` | 1 | 改为单进程并申请只读提权，成功读取 |
| 单进程沙箱读取仍被拒绝 | 2 | 使用 `require_escalated` 完成只读检查 |
| 更新规划文件时目标小节不存在，补丁校验失败 | 1 | 按现有标题重新定位并新增“技术决策”小节 |
| Hook/目录检索命令因最后一个 `rg` 无匹配返回退出码 1 | 1 | 有效只读输出已保留；后续将可选搜索视为允许无匹配 |
| 更新规划时再次使用了不存在的英文模板标题 | 2 | 拆成仅按已存在中文段落定位的小补丁 |
| 实施计划大补丁有一行缺少补丁前缀，整体写入失败 | 1 | 缩短计划并重新生成完整合法补丁，未留下半成品 |
