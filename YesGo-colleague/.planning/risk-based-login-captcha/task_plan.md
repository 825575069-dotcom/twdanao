# 风险触发式登录验证码计划

## 目标
在连续登录失败三次后，由 Django 服务端要求弹窗行为验证码，并使用一次性 token 防止绕过和重放。

## 当前阶段
阶段 6：审计、守卫与完整验收

## 阶段
- [x] 阶段 1：风险键、可信 IP 与失败计数
- [x] 阶段 2：服务端 challenge 与一次性 token
- [x] 阶段 3：登录和验证码 API
- [x] 阶段 4：前端 challenge 与 Modal
- [x] 阶段 5：总控/租户登录流程迁移
- [ ] 阶段 6：审计、守卫与完整验收

## 关键决策
- 账号 + IP + 入口计数，租户额外加入租户 ID。
- 15 分钟内失败 3 次，第 4 次开始强制验证码。
- challenge 和 token 均由服务端签发与校验，token 单次使用。
- Redis/cache 异常安全失败。
